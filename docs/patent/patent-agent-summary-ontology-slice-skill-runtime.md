# 代理人易改写版一页摘要：一种将面向任务的本体切片演进为技能运行时正式输入的方法

## 1. 一句话概括发明

本发明提供一种将领域本体中与当前任务相关的最小语义子图抽取为任务导向本体切片，并经投影文件、契约索引、请求时路由解析和阻断检查转换为技能运行时正式输入的方法，使语义资产能够在运行时被自动发现、动态路由、正式阻断和受控治理。

## 2. 现有技术核心缺陷

现有方案主要有四类不足：

1. 直接使用完整本体或其摘要，输入过大，运行时需要自行裁剪，容易引入无关语义和错误推断。
2. 本体的局部抽取结果通常只作为 Markdown、JSON 或模式文档存在，缺少从本体切片到消费技能可消费输入的正式转换层。
3. 投影文件或契约文件即使存在，也往往未进入技能加载器和技能运行时的正式接线，不能自动发现、不能按请求动态选择。
4. 在主题不明确、视图冲突、投影文件不完整、未决问题未解决或多生产方结果打平时，现有系统通常没有正式阻断机制，而是默认继续执行。

## 3. 本发明的核心技术方案

本发明的核心不是单一文件格式，而是一条完整运行链路：

`领域本体 -> 任务导向本体切片 -> 定向投影文件 -> 契约索引 -> 加载发现 -> 请求时主题解析 -> 请求时目标视图解析 -> 阻断检查 -> 运行时注入`

该方案至少包含以下关键步骤：

1. 从完整领域本体中围绕当前任务抽取最小语义闭包，得到包含概念、关系、约束和来源的本体切片。
2. 将本体切片投影为至少一种目标视图对应的投影文件，所述目标视图包括领域模型视图、数据结构约束视图、提示约束视图、工作流契约视图中的一种或多种。
3. 通过契约索引显式组织生产方、主题、目标视图、路径、评分规则和默认策略。
4. 由技能加载器自动发现契约索引并绑定到技能定义。
5. 在请求时而不是重载阶段，对候选主题进行评分并选择。
6. 在已选主题内继续对目标视图进行评分并选择。
7. 对选定投影文件执行阻断检查，包括歧义、缺文件、解析失败、状态不可消费、未决问题阻断和多生产方同分阻断。
8. 在通过阻断检查时，从投影文件中提取提示补丁或其他运行时控制输入并注入技能运行时。

## 4. 相对现有技术的关键创新点

### 创新点 1

把本体切片从离线知识整理产物变成运行时正式输入，而不是旁证材料或人工参考资料。

### 创新点 2

引入双层请求级路由机制，即先按当前请求选择主题，再在主题内选择目标视图，而不是依赖静态模板或默认配置。

### 创新点 3

把阻断检查作为正式运行时治理机制，只要主题、视图、投影文件完整性或多生产方裁决不能成立，即阻断而不是继续猜测。

### 创新点 4

支持多生产方契约并存，并采用“评分值优先、生产方优先级次优先、完全同分时阻断”的受控合流机制。

### 创新点 5

明确区分生产方模板治理与运行时契约治理，解决“模板合法但运行时不可消费”的边界混乱问题。

## 5. 建议重点保护的技术点

以下内容建议优先进入独立权利要求或作为从属权利要求的核心展开点。

### A. 主保护点

1. 任务导向本体切片的抽取，不是直接使用完整领域本体，而是围绕当前任务保留最小语义闭包。
2. 本体切片到投影文件的目标视图投影机制，使同一语义闭包能够面向不同消费技能场景交付。
3. 契约索引作为运行时机器路由入口，用于组织主题、视图、路径、评分规则和默认策略。
4. 请求时路由解析，即主题和目标视图的选择均在请求到达时基于当前请求执行。
5. 阻断检查与运行时注入的串联关系，即只有在通过阻断检查后，投影文件才能成为技能运行时正式输入。

### B. 次保护点

1. 投影文件中至少包含映射策略、提示投影、交付物、裁剪项、未决问题中的一种或多种。
2. 阻断条件包括主题歧义、视图歧义、投影文件缺失、解析失败、视图状态不可消费、未决问题阻断和多生产方无法打破同分歧义。
3. 多生产方的裁决规则为：分别解析、统一排序、生产方优先级作为同分裁决依据、完全同分时阻断。
4. 加载发现诊断信息采用未发现、已绑定、部分绑定、解析失败、枚举失败等状态区分发现和绑定结果。
5. 生产方模板模式与运行时契约模式分层治理，分别服务于离线生成校验与在线消费校验。

## 6. 独立权利要求建议骨架

独立权利要求建议围绕以下组合方案展开：

1. 基于任务从领域本体抽取最小语义闭包形成本体切片。
2. 将本体切片投影为至少一种面向消费技能的投影文件。
3. 基于投影文件构建或维护契约索引。
4. 由加载器自动发现并绑定契约索引。
5. 在请求到达时执行主题与目标视图的动态路由。
6. 对所选投影文件执行阻断检查。
7. 在通过阻断检查时，将投影文件转换为运行时正式输入并注入技能运行时。

上述 7 步建议整体写入主权，避免保护范围被压缩成单点文件结构或单一评分算法。

## 7. 从属权利要求可展开方向

1. 本体切片的字段组成：概念、关系、约束、来源。
2. 投影文件的目标视图类型：领域模型视图、数据结构约束视图、提示约束视图、工作流契约视图。
3. 契约索引的字段：生产方标识、生产方优先级、主题评分规则、目标视图评分规则、默认选择策略、路径。
4. 请求时路由的阈值差或歧义判定机制。
5. 阻断检查的具体条件。
6. 多生产方的评分值和优先级排序规则。
7. 运行时注入内容：允许术语、禁止性假设、必要澄清项、推理路径、来源摘要、裁剪项。
8. 生产方模板治理与运行时契约治理的分层校验机制。

## 8. 代理人改写时的注意事项

1. 不要把方案写窄成某个具体技能、某个固定目录结构或某个具体文件名实现。
2. 不要把创新点写成“使用 JSON 文件”或“使用模式校验”，真正的核心是本体切片、投影文件、路由、阻断、运行时注入的组合关系。
3. 主权要强调“请求级动态选择 + 阻断后才能注入技能运行时”这一控制链条，这是区别于普通知识整理和静态提示模板的重要特征。
4. 从权可适当覆盖多生产方、诊断信息、治理分层和多目标视图，以增强稳定性和防绕过能力。

## 9. 建议给代理人的一句话提示

这项发明的保护重点不是领域本体本身，而是“如何把任务导向本体切片通过投影文件和契约路由机制，变成技能运行时在每次请求中可正式消费且可阻断治理的输入”。
