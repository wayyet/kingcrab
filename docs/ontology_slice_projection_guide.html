Ontology、Slice、Projection 概念说明

这是一份面向企业数字化、知识图谱、数据治理与 AI Agent 场景的入门说明。它帮助你快速理解：什么是本体（Ontology），为什么需要切片（Slice），以及什么是投影视图（Projection）。

Ontology： 定义企业世界“有什么、怎么关联、遵循什么规则”。
Slice： 从完整本体中，按场景切出一块可用的局部语义模型。
Projection： 从某个视角，把本体或切片表达成当前任务需要的语义视图。

1. 为什么会出现这些概念

在企业数字化环境中，不同系统、不同部门、不同角色，对同一个业务对象往往有不同叫法和不同表示方式。结果就是：系统难集成，数据难对齐，AI 也难以稳定理解业务世界。

术语不统一
同一个对象，在 ERP、MES、CRM、报表里可能名字不同、口径不同。
语义不一致
数据能对上字段，但不代表能对齐业务含义与规则。
AI 缺上下文
没有稳定语义基础时，AI 只能“猜”，难以可靠协作与推理。
因此，企业需要一套稳定的语义骨架来描述“对象、关系、规则”，这就是 Ontology。

2. 什么是 Ontology

通俗理解

如果把企业看成一个复杂世界，那么 Ontology 就是在回答三个问题：

  • 这个世界里 有什么
  • 这些东西之间 是什么关系
  • 它们 遵循什么规则
制造业例子： 产品、物料、工单、工艺路线、设备、工位、检测项、缺陷、供应商……这些对象之间有结构化关系，也有业务约束。
概念 它回答什么 与本体的区别
数据表 数据怎么存 本体回答“这些数据在业务世界里是什么意思”
流程图 活动顺序与流转 本体更强调对象、关系与约束
术语表 词语是什么意思 本体不仅解释词，还定义词之间的结构化关系

3. 什么是 Slice

一句话

Slice = 从完整本体中，切出一块局部语义子模型

它是围绕某个业务主题、角色、范围或任务切出来的，不是“随便挑几个字段”，而是保留必要概念、关系和约束的一块语义内容。

常见切法

  • 按业务域：销售、采购、生产、质量、财务
  • 按角色：客服、计划员、财务审核员、采购专员
  • 按流程阶段：订单受理、排产、生产执行、售后服务
  • 按对象范围：设备运维、合同审查、主数据治理

4. 什么是 Projection

一句话

Projection = 从完整本体或某个切片中，按特定视角、维度或用途形成的语义视图。

如果 Slice 更像“切一块下来”，那么 Projection 更像“从某个角度看过去，只保留你关心的那部分”。

  • 给现场工程师看：设备参数、工位、缺陷分布
  • 给管理层看：不良率、趋势、责任归因、风险预警
  • 给 AI Agent 看：可推理对象、规则约束、上下文结构

Projection 的常见表现形式

  • 角色视图：计划员、客服、财务审核员各自看到的业务视图
  • 任务视图：合同审查、缺陷分析、排产优化等任务专属语义视图
  • 系统视图：API、报表、Agent 运行时上下文、数据映射视图
  • 分析视图：经营分析、质量根因分析、供应风险分析等

5. Ontology、Slice、Projection 三者的关系

Ontology

定义完整业务世界的语义骨架，说明有哪些对象、关系和规则。

Slice

按主题、范围或角色，从完整本体中切出一块局部语义子模型。

Projection

按用途、视角或任务，把本体或切片表达为可直接使用的语义视图。

最自然的工程路径是：Ontology → Slice → Projection
地图比喻： Ontology 是整张地图；Slice 是从地图上切出一块区域；Projection 是在这块地图上只显示地铁线路、医院或学校等你关心的信息。

6. 在行业本体与企业本体中的应用

行业本体

描述某个行业中相对通用、可复用的概念体系。

  • 制造业：产品、BOM、工艺路线、工单、工位、设备、缺陷
  • 零售业：门店、商品、促销、库存、会员、交易
  • 金融业：客户、账户、交易、风险、产品、合规规则

企业本体

描述某家企业自己的特定语义结构。

  • 组织架构、岗位定义、系统编码
  • 流程规则、指标口径、审批逻辑
  • 主数据映射关系、业务特例与企业规范
关键点： 一个真正可用的 Slice，往往来自“行业本体 + 企业本体”的结合。例如“计划员智能体 Slice”既需要行业层的订单、产能、物料、工艺路线，也需要企业层的工厂结构、排产规则、ERP/MES 编码和优先级策略。

7. 在 AI Agent 场景里如何理解这三个概念

为什么 Agent 需要 Ontology

  • 帮助 Agent 稳定理解企业世界中的对象与关系
  • 支撑规则约束、术语统一与跨系统协同
  • 降低仅靠提示词“临时猜测”的不稳定性

为什么不能每次都加载完整本体

  • 完整本体太大，成本高，噪声多
  • 不同智能体只需要知道与自己任务相关的一小部分
  • 按 Slice 和 Projection 组织上下文，更利于推理与治理

一个典型链路

  1. 沉淀行业本体与企业本体
  2. 面向岗位或智能体类型设计多个 Slice
  3. 面向具体任务生成 Projection
  4. Agent 在执行时加载对应 Projection，而不是整个本体

例子： 财务审核员智能体的 Slice 可能包含合同、发票、付款申请、预算科目、审批权限和审核规则；而在“审批某一笔付款”任务里，Projection 只保留当前申请单及其相关规则与上下文。

8. 容易混淆的几个点

Slice 不是简单挑几个字段

它本质上仍是一个语义子模型，应该保留必要的核心概念、关键关系和基本约束。

Projection 不只是 UI 展示

它也可能是 Agent 运行时上下文、API 语义视图、数据映射视图或分析任务视图。

本体不是越大越好

不是“越全越厉害”，而是“越能支撑协同、集成、治理与 AI 应用越好”。

区分的小诀窍

Slice 强调“切出来的一块范围”；Projection 强调“从某个视角呈现出来的样子”。

9. 一页式总结

Ontology 负责定义世界，Slice 负责切出场景，Projection 负责表达视图。
概念 核心作用 最简定义
Ontology 定义完整语义骨架 定义企业或行业中有哪些对象、这些对象如何关联、遵循什么规则
Slice 面向场景裁剪范围 针对特定业务主题、角色、部门或任务，从完整本体中裁剪出的局部语义子模型
Projection 面向视角进行表达 从完整本体或某个切片中，按特定视角、维度或用途形成的语义视图
在企业 AI Agent 体系里：
本体解决“Agent 要理解什么世界”；
Slice 解决“这个 Agent 应该知道哪一部分世界”；
Projection 解决“这个 Agent 在当前任务里应该看到这个世界的什么样子”。
