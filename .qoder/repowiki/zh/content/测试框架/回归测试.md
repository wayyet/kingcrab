## 简介
本文件面向回归测试子系统，系统性阐述回归测试运行器的实现原理、场景选择与执行流程、报告生成与摘要统计、状态解析与严格模式、退出码计算、场景分类筛选、结果标准化与推荐系统等机制。同时提供配置方法、执行策略、报告解读与问题排查的实用指南，帮助开发者与运维人员高效开展回归测试工作。

## 项目结构
回归测试相关代码主要位于 OpenClaw.Testing 命名空间中，围绕“运行器 + 场景集合 + 报告输出 + CLI 命令”组织，形成清晰的分层与职责分离：
- 运行器：负责构建上下文、选择场景、执行场景、标准化结果、汇总统计、计算整体状态与退出码、生成推荐建议。
- 场景集合：内置多类回归场景（配置加载、安全加固、工具审批策略、内存/会话持久化、序列化一致性、MCP/兼容请求形状、学习策略、托管技能校验、部署配置、文档存在性等）。
- 报告与输出：提供文本与 JSON 格式报告；支持按运行 ID 写入磁盘并生成 Markdown 报告。
- CLI 命令：提供初始化、运行、报告重生成、质量门禁等子命令，支持失败策略控制。

## 核心组件
- 运行器（HarnessRegressionRunner）

  - 提供 init/run/report/gates 子命令，支持失败策略（any/high）、输出目录、场景目录等参数。

## 详细组件分析

### 运行器：HarnessRegressionRunner
- 上下文构建
  - 解析配置路径（支持显式与默认路径），尝试加载 GatewayConfig，记录错误信息；根据 Offline 与 Strict 参数设置上下文属性；创建临时工作区目录。
- 场景选择
  - 支持按 Category 过滤，默认返回全部场景；过滤时进行大小写与空白规范化。
- 执行流程
  - 逐个场景执行，支持取消；每个结果先标准化（状态/严重度归一、时间戳与耗时修正、必填字段回退）；收集结果后构建摘要（总数、通过/失败/跳过/警告/不适用）。
- 整体状态解析
  - 任一 Required 场景失败 → 整体失败；Strict 模式下，Required 的 Warning 或 Skipped → 视为失败；否则若存在 Warning → 整体 Warning；否则整体 Passed。
- 推荐系统
  - 基于结果特征生成“下一步”建议，如快速开始配置检查、安全态势审查、模型配置校验、查看跳过项说明等。
- 退出码
  - 若存在 Required 且失败的场景 → 退出码 1；Strict 模式下，Required 的 Warning/Skipped → 退出码 1；否则 0。
- 清理
  - 无论成功与否，最终清理临时工作区目录（忽略 IO/权限异常）。

## 性能考量
- 场景执行并发
  - 当前实现为顺序执行，避免共享资源竞争；若场景间无依赖，可在扩展点引入并行执行以提升吞吐。
- 临时工作区管理
  - 使用独立临时目录隔离场景数据，结束后删除；注意磁盘 IO 与权限开销。
- 序列化与报告
  - JSON 序列化采用源生成上下文，性能较优；文本报告构建为一次性字符串拼接，适合中小规模结果集。
- 离线模式
  - Offline 模式跳过网络与凭证检查，显著降低外部依赖带来的不确定性与耗时。

## 故障排查指南
- 无场景匹配
  - 若指定 Category 但没有匹配场景，运行器会生成一条“未选择到场景”的失败结果，建议检查类别名称大小写与拼写。
- 配置加载失败
  - 配置文件不存在或解析异常时，上下文会记录错误信息；建议确认配置路径与格式正确。
- 严格模式导致失败
  - 在 Strict 模式下，Required 的 Warning/Skipped 会被视为失败；可通过关闭严格模式或修复场景来解决。
- 临时目录清理失败
  - 运行器在 finally 中尝试删除临时目录，若被占用或权限不足可能失败；可手动清理或调整权限。
- Agent 场景质量门禁失败
  - 若场景缺少 id/title、无明确期望、高危场景缺少安全/审批 Oracle、工具使用场景缺少工具声明等，将触发门禁失败；请根据错误提示补齐场景定义。
- 退出码非零
  - 由运行器根据 Required 场景状态与严格模式决定；建议结合报告摘要与推荐建议定位问题。

### 测试框架详解
本节聚焦 OpenClaw 测试框架除运行器/CLI/报告之外的三块底盘：场景数据模型（ScenarioModels）、场景加载器（ScenarioLoader）、测试插件夹具（FixturePlugins），以及它们如何与 ScenarioHarness、HarnessRegressionRunner 协同。

#### 场景数据模型（ScenarioModels）
场景数据层定义了从“场景定义”到“运行轨迹”再到“运行结果与报告”的完整对象链，全部为 init-only 的不可变 record/sealed class，便于序列化与并发安全。

- 场景定义（AgentScenario）
  - 关键字段：Id、Title、Description、Risk（ScenarioRisk 枚举：Low/Medium/High/Critical）、Type（默认 "agent"）、Tags、Input、Expected、Oracles、ScriptedTrace、Metadata。
  - Risk 枚举使用 JsonStringEnumConverter 序列化为字符串，与 JSON 场景文件中的 "low/medium/high/critical" 直接互通。
- 场景输入（ScenarioInput）
  - UserMessage、Context（上下文片段列表）、Variables（OrdinalIgnoreCase 字典）。
- 场景期望（ScenarioExpected）
  - 工具维度：MustCallTools、MustNotCallTools、MaxToolCalls。
  - 输出维度：FinalAnswerContains、FinalAnswerMustNotContain。
  - 安全维度：RequiresApproval。
  - 状态/事件维度：ExpectedState、ExpectedEvents、ForbiddenEvents。
- Oracle 定义（ScenarioOracleDefinition）
  - Type（断言类型字符串，对应 ScenarioOracles 的注册类型）、Tool、Value（任意 JsonElement）、Limit、Tools、Metadata。
- 脚本化轨迹（ScriptedTrace / TraceStep）
  - ScriptedTrace 包含 FinalAnswer、Status（默认 ScenarioRunStatuses.Completed）、Steps、Metadata。
  - TraceStep 字段覆盖 Reasoning/ToolCall/ToolResult/StateChange/Event/ApprovalRequest/Error 七类（TraceStepKinds 常量）；含 ToolName、ArgumentsJson、Result、Error、StatePath、From/To、ApprovalId 等可选位。
- 运行结果与报告
  - ScenarioRunResult：Scenario + Trace + OracleResults + Passed + 起止时间 + FailureSummary。
  - ScenarioRunReport：RunId + 起止时间 + Summary + Results + 渲染好的 Markdown。
  - ScenarioRunSummary：Total/Passed/Failed/HighOrCriticalFailures。
  - TraceWriteResult：落盘后的目录、results.json 路径、Markdown 报告路径、各场景 trace 文件路径。
- 状态常量
  - TraceStepKinds：reasoning/toolCall/toolResult/stateChange/event/approvalRequest/error。
  - ScenarioRunStatuses：unknown/completed/failed。

#### 场景加载器（JsonScenarioLoader）
JsonScenarioLoader 实现 IScenarioLoader 协议，负责把磁盘上的 *.json 场景定义批量加载为 AgentScenario 对象，并做严格的字段归一化以保证下游 Harness/Oracle 不被空值/大小写/缺省值困扰。

- 目录扫描
  - 若 directoryPath 不存在，返回空列表（与“无场景目录”的语义一致，由运行器另行报告）。
  - 使用 Directory.EnumerateFiles 递归（SearchOption.AllDirectories）匹配 *.json，按 StringComparer.Ordinal 排序，确保跨平台执行顺序稳定。
- JSON 兼容形态
  - 单对象：直接反序列化为 AgentScenario。
  - 数组：反序列化为 List&lt;AgentScenario&gt;，逐个 Normalize 后追加。
  - 反序列化通过 ScenarioJsonContext.Default 源生成上下文执行，AOT-friendly 且零反射。
- 归一化（Normalize 系列）
  - AgentScenario：Id/Title 缺省 ""、Type 缺省 "agent"、空集合一律归一为空 List 而非 null。
  - ScenarioInput：UserMessage 缺省 ""、Variables 转 OrdinalIgnoreCase 字典。
  - ScenarioExpected：所有 List 字段补空，MaxToolCalls/RequiresApproval 保留可空语义。
  - ScenarioOracleDefinition：Type 缺省 ""、Tools/Metadata 归一。
  - ScriptedTrace：Status 缺省 ScenarioRunStatuses.Completed，Steps 与 Metadata 归一。
  - TraceStep：Kind 缺省 TraceStepKinds.Event。
  - Metadata：统一使用 OrdinalIgnoreCase 字典，避免大小写引起的状态丢失。

#### 测试插件夹具（FixturePlugins）
OpenClaw.TestPluginFixtures.ToolAndCommandPlugin 实现 INativeDynamicPlugin，是回归与端到端测试用的“最小完整”原生动态插件样板，覆盖工具注册、命令注册、内存提供方注册、托管服务注册四类扩展点。

- 工具与命令
  - RegisterTool(new EchoTool())：注册名为 "native_dynamic_echo" 的 ITool，输入 schema 仅含必填 text 字符串，输出形如 "native:&lt;text&gt;"。
  - RegisterCommand("native_dynamic_echo", ...)：注册同名 CLI 命令，输出形如 "cmd:&lt;args&gt;"，与工具形成对照，便于在脚本场景里同时校验两条路径。
- 配置驱动的扩展
  - 通过 INativeDynamicPluginContext.Config（JsonElement）按需读取 startPath/stopPath/memoryProviderId 三个字段，使用私有 TryGetConfigValue 做严格的对象+字符串+非空判断，避免无效配置导致空注册。
- 内存提供方注册
  - 当配置含 memoryProviderId 时，调用 RegisterMemoryProvider，使用 providerContext.GatewayConfig.Memory.StoragePath 构造 FileMemoryStore 注入回核心，覆盖测试场景里的“可插拔记忆后端”需求。
- 生命周期 MarkerService
  - 当 startPath 或 stopPath 任一非空时，注册一个实现 INativeDynamicPluginService 的 MarkerService。
  - StartAsync：把 "started" 写入 startPath；StopAsync：把 "stopped" 写入 stopPath。
  - 该机制为测试断言“插件启停顺序”提供了文件层证据，避免依赖日志或时序观察。
