# 评估评分标准

## 评分维度

### 1. 功能完整性 (Functionality Completeness)

评估目标沙箱对测试用例要求的满足程度。

| 指标 | 说明 |
|------|------|
| 需求覆盖 | 是否覆盖了测试用例中的所有功能点 |
| 正确性 | 每个功能点的实现是否正确 |
| 边界处理 | 对边界条件和异常输入的处理是否恰当 |

### 2. 交互质量 (Interaction Quality)

评估目标沙箱与用户交互的体验。

| 指标 | 说明 |
|------|------|
| 响应连贯性 | 多轮对话中的上下文保持和逻辑连贯 |
| 信息呈现 | 输出信息的结构、清晰度和可读性 |
| 用户引导 | 对用户意图的理解和恰当引导 |

### 3. 响应准确性 (Response Accuracy)

评估目标沙箱输出的正确性。

| 指标 | 说明 |
|------|------|
| 事实正确性 | 输出内容的事实是否准确 |
| 工具使用 | 工具调用的选择和参数是否正确 |
| 推理逻辑 | 思考链路中的推理是否合理、无矛盾 |

### 4. 效率性能 (Efficiency & Performance)

评估目标沙箱的执行效率。

| 指标 | 说明 |
|------|------|
| 响应时间 | 单轮响应的时间延迟 |
| 步骤精简 | 完成任务所需的步骤是否最优 |
| 资源使用 | 工具调用、Token使用是否合理 |

## 评分等级

| 等级 | 分数范围 | 描述 |
|------|----------|------|
| 优秀 (A) | 90-100 | 完全满足甚至超出预期，无明显缺陷 |
| 良好 (B) | 80-89 | 满足主要需求，有少量可优化点 |
| 合格 (C) | 70-79 | 基本满足需求，存在可改进之处 |
| 待改进 (D) | 60-69 | 部分需求未满足，存在明显缺陷 |
| 不合格 (F) | 0-59 | 严重缺陷，无法满足基本需求 |

## 评分流程

1. 获取该领域的详细评分标准（通过 `Get-ScoringCriteria` 脚本）
2. 对照执行过程跟踪逐条检查
3. 按维度汇总评分
4. 加权计算总分（默认各维度等权重）
5. 撰写每个维度的评分说明和改进建议
